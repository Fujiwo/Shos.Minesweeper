## 書き方

出来事が起きたその場で、1 件を表の 1 行として追記する。後から思い出して書かない。

### 書くきっかけ

| きっかけ | 書くこと |
|----------|----------|
| スキルを呼んだとき、reference を読んだとき | 作業の種類、読んだ reference と節。その作業の「必ず読む」を読まなかったときは、そのこと |
| スキルで判断が変わったとき | 何がどう変わったか。スキルのどの規則・節か |
| スキルに従った判断を採らなかったとき | 採らなかった理由（CLAUDE.md、ユーザーの指示、既存の流儀など） |
| 七箇条に当てはまらない指摘が出たとき | その指摘と、「整合」「正しさ」のどちらで拾ったか |
| 臭いの表にない症状の名前で指摘したとき | その名前（表に足す候補になるかの材料） |
| 工程 13 などで不具合が見つかったとき | どの工程のどの観点なら拾えたか。スキルの範囲の内か外か |
| ユーザーが Claude の判断を直したとき | 直された判断がスキル由来だったか。どの規則か |
| スキルと CLAUDE.md・ユーザーの指示がぶつかったとき | どちらに従い、なぜか |
| スキルの文言で迷ったとき | 迷った箇所と、どう解釈したか（改善案の材料） |
| 工程を承認されたとき | その工程でのスキルの使われ方の要約を 1〜3 行 |

### 判定の区分

skill-evaluation.md の 1.2 と同じ区分を使い、その場で決める。

| 区分 | 意味 |
|------|------|
| スキル | スキルがあったから起きた。スキルの規則・節を具体的に指せる |
| スキルなし | スキルがなくても起きたと思われる。CLAUDE.md やユーザーの指示、ほかの手順が直接の理由である |
| 判別できない | どちらとも言えない |
| — | 判定の対象でない（読んだことの記録、条件の変更など） |

- スキルの語で言い換えただけのものは「スキル」にしない。
- 「スキルなし」「判別できない」も、効かなかったことの記録として同じ重みで書く。
- 根拠は、本文を写さず、場所（code-review.md の区切りと指摘の番号など）を指す。

### 一巡の最後に数えるもの

基準（skill-evaluation.md）と同じ物差しで比べる。

- レビューの指摘の数を、観点（七箇条の各箇条、引き算、整合、正しさ）ごとに
- 指摘とリファクタリングの対象のうち、臭いの表の名前を使った割合
- 「必ず読む」を守った割合（作業の種類ごと）
- 工程 13 以降で見つかった不具合の数と、拾えたはずの工程・観点
- ユーザーに直された判断の数と、そのうちスキル由来のもの
- 判定の区分ごとの件数
