## 観点

1. **完全性**: CLAUDE.md の「UI デザイン」に挙げた項目がすべてあるか。仕様書で決めた操作と表示が、すべて画面に落とし込まれているか
2. **一貫性**: 仕様書と矛盾していないか。節どうしで矛盾していないか
3. **曖昧さ**: 同じ文から二通りの実装が生まれる箇所がないか
4. **アクセシビリティ**: WCAG 2.2 のレベル AA（仕様書 6.3）を満たすか。コントラスト比は計算し直して確かめる
5. **使いやすさ**: 小さい画面とタッチで、誤操作や見落としが起きないか

重大度の基準は、調査書レビュー（docs/reviews/01-research-review.md）と同じとする。

## 確かめたこと

- 4.1 と 4.3 のコントラスト比を、WCAG の相対輝度の式で計算し直した。表の値と一致した。
- 3.3 のマスの大きさの表を、3.2 の規則で計算し直した。表の値と一致した。
- 盤面が下限の 20px でも収まらない場合（表の S）の向きの選び方も確かめた。3.2 の規則は、切り捨てと下限を当てはめる前の値で比べるので、二つの向きが同じ値になって決まらない、ということは起きない。「スクロールせずに見える割合が大きいほう」で選ぶ規則とも比べたが、表のすべての場合で結果は同じだった。規則は変えない。

## 良い点

- 仕様書の見込み（PC の上級で 36px 以上、カスタムの最大で 24px 以上）を、寸法を決めたうえで計算で確かめている。ツールバーの高さを増やすと 24px を下回る、という注意も書かれている。
- 横向きのスマートフォンでツールバーを横に移すことで、仕様書 5.2 の見込みより上級のマスを大きくできている。
- 配色を名前（トークン）で定め、主な組み合わせのコントラスト比を表にしている。配色を変えるときに、どこを計算し直せばよいかが分かる。
- 旗の布のように 3:1 に届かない組み合わせを隠さずに書き、縁取りで補う理由を示している。
- 長押しの円を指より大きくし、成立したときの操作（旗かスコップ）をアイコンで示している。旗モードで長押しの意味が逆になることを、押している間に確かめられる。
- 仕様書で決まっていなかった点を 8 章に集め、理由を付けている。

## 残る課題

- 数字の色、長押しの円の大きさ、振動の長さは、実機で見て調整する（工程 13、15）。9 章に記載済み。
- 3.3 の表の画面の大きさは仮定の値である。実機での確認で、マスの大きさが見込みから大きく外れる端末があれば、3.1 の寸法を見直す。

### 良い点

- 色のトークンを 2 つ足すだけで、今の色とコントラスト比の表（4.1、4.3）をそのまま使っている。様式を変えても、1.0.0 で確かめたアクセシビリティを崩していない。
- 10.4 で、見た目の配置だけを変え、マスの大きさの計算（3.2）と寸法を変えていない。3.3 の表と、1.0.0 で確かめた 48 通りのマスの大きさが、そのまま成り立つ。
- 演出の長さを、操作から最初の変化までの時間（仕様書 6.2）と、仕様書レビューの残る課題（波が届く前のマス）の両方から決めている。
- 効果音を、聞こえ方と合成の目安の両方で書き、試聴のページで確かめられるようにした。

### 残る課題

- マウスで指したときの色（`cell-closed-hover`）と `cell-open` の比は 2.84 で、1.0.0 から 3:1 に届いていない。指している 1 つのマスだけの一時的な状態で、1.1.0 ではタイルの周りに板の色の線（6.41。ライト）が見えるので、区別はできる。直さない。
- 試作は、ツールバーの位置と勝利カードの位置をスクリプトで合わせて撮った。実装の方法はアーキテクチャー設計で決める（10.9）。
- 音の設計と演出の長さは、実機で調整する（工程 13、15）。
