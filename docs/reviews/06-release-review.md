### ユーザーの確認と、最初のクリックの音の遅れ

ユーザーが、PC の Edge と Firefox で確かめた（受け入れ基準 14）: 「最初のクリックから効果音が鳴る。ただし、ロード後の最初のクリック時は音が少し遅れる」。

遅れを、公開したサイトで切り分けた（ヘッドレスの Chrome。押す・離す・`AudioContext` の作成と `running`・再生の指示の時刻を測った）。

| | 押してから再生の指示まで | 内訳 |
|---|---|---|
| 1 回目のクリック（押している時間 100 ミリ秒） | 203〜361 ミリ秒 | 押したときに `browser.js` が作る `new AudioContext()` が、63〜207 ミリ秒、ページの処理を止める（音声出力を開くため）。止まっている間は、離したイベントの処理も遅れる。6 つの `AudioBuffer` の作成は 1 ミリ秒未満。離してから再生の指示までの .NET の処理は 12〜26 ミリ秒 |
| 2 回目のクリック | 2 ミリ秒 | `AudioContext` はもうある |

- 原因: ブラウザーは、最初の操作で `AudioContext` を作るときに音声出力を開く。1 回目だけ、音と、マスが開く見た目が、その分（0.1〜0.2 秒ほど）遅れる。
- 試した直し方: ページを開いたときに（操作を待たずに）`AudioContext` を作っておき、最初の操作では `resume()` だけにする形を、作業用のコピーで測った。ページが止まることはなくなった（離したイベントはすぐに処理された）が、止まった状態で作った `AudioContext` が動き出すまでに 690〜830 ミリ秒かかり、最初の音はかえって大きく遅れた。Chrome はコンソールに警告も出す（アーキテクチャー設計書 9.4 で、この形を採らなかった理由）。
- ユーザーの判断（2026-09-27）: 既知の制約として記録し、コードは変えない。リリースノートの 1.1.0 の「知っておいてほしいこと」に書き足し、アーキテクチャー設計書 9.4 に、測った結果と採らなかった形を書いた。
