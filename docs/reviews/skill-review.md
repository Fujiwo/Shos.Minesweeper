## 観点

1. **2 版の一致**: 英語版と日本語版が、行・構造・リンク・出典で対応しているか。
2. **参照の正しさ**: リンク先のファイルと、「〇〇.md の『節』」の形の節の参照が実在するか。
3. **整合**: SKILL.md と reference の間、今回入れた改善案と既存の文の間で、指示が食い違っていないか。
4. **起動の条件**: description と、作業の表の範囲が合っているか。
5. **表記**: 誤字、余分な空白。

1 と 2 はスクリプトで全行を機械的に確かめた。3〜5 は、SKILL.md の全体と、改善案を入れた箇所の前後（quality-gates.md の「七箇条をレビューの観点にする」から「ガード節」まで、testing.md の「フィードバックの種類」から「TDD の進め方」まで、refactoring.md の対応表）を読んで確かめた。reference のそのほかの節は、見出しと参照の確かめだけで、文の意味までは読み直していない。

## 4. 見送るもの

| 候補 | 見送る理由 |
|------|------------|
| SKILL.md のセルフチェックや完了報告の「検証結果」に、本番の実行環境での確認（S2）を足す | 「検証結果」は「実際に実行したものと、検証できなかったこと」を書く形で、本番の環境で動かしたかどうかも、そこに書ける。testing.md の表で足りる。足すと、小さな変更にも毎回問う項目が増える |

| description の二つの版の書き分け（先頭の、版を選ぶ文） | 互いに譲る形で書かれ、2 つの一巡で誤って選ばれた記録がない（skill-evaluation.md の 6.2） |
