## 観点

Web 版の UI デザインレビュー（docs/reviews/03-ui-design-review.md）の観点に、この一巡の条件を加えた。

1. **仕様との一致**: 仕様書（docs/desktop-console/02-spec.md）の操作と表示が、すべて画面に落とし込まれているか。仕様書と食い違っていないか
2. **曖昧さ**: 寸法や規則から、二通りの実装が生まれる箇所がないか。計算が合っているか
3. **使いやすさ**: 想定する利用者（PC のマウスとキーボード、端末のキーボード）にとって自然か。端での動き（小さいウィンドウ、狭い端末、誤った入力の繰り返し）で崩れないか
4. **アクセシビリティ**: 色だけに頼らないか、キーボードで操作できるか、読み上げの名前があるか
5. **Web 版との一貫性**: デスクトップ版が Web 版の定義を正しく指しているか。同じ定義を 2 か所に書いていないか

重大度の基準は、調査書レビュー（docs/desktop-console/reviews/01-research-review.md）と同じとする。

## ユーザーの確認事項の扱い

UI デザインの提出時に、次の 3 点を確認事項として挙げた。ユーザーは個別の回答をせずに工程を承認したので、前例に従い、**推した案どおりに確定した**ものとして扱う。

| 確認事項 | 確定した内容 |
|----------|--------------|
| デスクトップ版の既定のマスの大きさ | 32px |
| コンソール版の記号とカーソル | 未開放 `#`、旗 `F`、地雷 `*`、踏んだ地雷 `@`、誤った旗 `X`。カーソルは角かっこ（色があれば反転表示も重ねる） |
| コンソール版の数字の色 | 1 青、2 緑、3 赤、4 紫、5 茶（DarkYellow）、6 水色、7 既定の文字色、8 暗い灰 |

## 指摘

| # | 重大度 | 観点 | 場所 | 指摘 | 対応 |
|---|--------|------|------|------|------|
| 1 | 中 | 曖昧さ | 2.2、2.4 | ウィンドウを盤面に合わせるときの中身の幅が決まらない。ツールバーの幅は「中身の幅 − 32px と 480px の小さいほう」だが、中身の幅を盤面とツールバーから決めるので、互いに相手に依存している。初級（盤面 294px）では、ウィンドウの幅が実装によって変わる | 中身の幅を「盤面の幅と 368px（ツールバーの最小の幅）の大きいほう + 32px」、高さを「盤面 + 52 + 4 + 32px」と式で書き、初級（400×382）と中級（550×606）の例を足した |
| 2 | 中 | 使いやすさ | 3.7 | コンソール版のカスタムの入力で、誤るたびに誤りの行と尋ね直す行が増える図と書き方になっていた。何度も誤ると、画面が端末の高さを超えて崩れる | 誤りの行は 1 行だけにし、同じ行で尋ね直す（入力を消して、カーソルを戻す）とした。図も改めた |
| 3 | 軽微 | 一貫性 | 2.3 | ワイヤーフレームで、ツールバーが盤面と同じ幅に描かれていたが、規則（2.2）ではツールバーの幅は 480px までで、上級では盤面より狭い | 図を上級の例として描き直し、ツールバーが盤面の中央の上に置かれることを書いた |
| 4 | 軽微 | 仕様との一致 | 3.2 | 初級の図（未開始）で、カーソルが 3 行目にあった。仕様書 5.3 は、カーソルの初めの位置を左上としている。初めて起動したときの図としては食い違う | カーソルを左上に描き直した |
| 5 | 軽微 | 曖昧さ | 2.11 | 勝利カードを出しているときに F2 を押したときの動きが書かれていない | 「もう一度」と同じく、新しいゲームを始めてカードを閉じるとした |
| 6 | 軽微 | 曖昧さ | 2.10 | OS の「アニメーション効果」の設定を、いつ読むかが書かれていない。起動したときだけ読むと、開いたまま設定を変えた利用者に従わない | 起動したときに読み、開いたまま変えたときも次の演出から従うとした（Web 版の `prefers-reduced-motion` と同じ）。知る方法は設計に送った |
| 7 | 軽微 | 一貫性 | 2.2 | ダークの配色で、OS の題名の帯だけが明るいままだと、見た目がそろわない。Avalonia で帯の明暗が配色に従うかを確かめていない | 表に項目を足し、実装で確かめる事項として 5 章に送った |
| 8 | 軽微 | 使いやすさ | 3.4 | コンソール版の 16 色のうち、明るい背景の端末では、黄（誤った旗）と水色（6）が読みにくいおそれがある | そのことと、記号で区別できるので遊べることを書いた。実機での調整は 5 章に送ってある |
| 9 | 軽微 | 使いやすさ | 3.8 | 「端末の画面を広げてください」の文は約 60 升あり、それより狭い端末では収まらない。どう出すかが書かれていない | 端末の幅で折り返してよいとした |

重大の指摘はなかった。

- 数えて確かめたこと: コンソール版の図の各行の表示の幅（盤面の行 63 升、キーの案内の行 76 升など）と、幅があいまいな文字がないことを、スクリプト（Unicode の East Asian Width）で確かめた。デスクトップ版の寸法（初級 400×382、中級 550×606、上級 998×606、最小の幅でのツールバーの間隔）を計算し直した。
- 捕まえなかった例外のときにデスクトップ版で何を見せるかは、画面の決定ではなく例外の境界の設計に関わるので、アーキテクチャー設計に送った（5 章）。

## 良い点

- デスクトップ版は、Web 版の UI デザインの節を指して「そのまま使う」とし、違う点だけを書いている。配色の値を写していないので、コントラスト比の表が 2 か所で食い違うことがない。
- コンソール版は、仕様書の「幅があいまいな文字を使わない」を、盤面の記号だけでなく文言（盤面の大きさの `x`）にまで当てはめている。
- コンソール版の寸法を、盤面の大きさから式で決めている（幅 2 × 列数 + 3、高さ 行数 + 6）。端末が小さいときの規則（3.8）と、そのまま結び付く。
- 色がなくても遊べることを、記号とカーソルの角かっこで保っている（仕様書 5.6 の `NO_COLOR`）。

## 残る課題

- デスクトップ版の見た目（タイルのグラデーション、影、書体）を、Web 版と並べた写真で確かめるのは、実装と結合テストで行う（5 章）。
- コンソール版の 16 色の見え方と、従来のコンソール ホストでの列のずれがないことは、実機で確かめる（仕様書 8.3 の基準 17）。
- 盤面を表として読ませる方法は、アーキテクチャー設計で決め、実装の最初の区切りで確かめる。
