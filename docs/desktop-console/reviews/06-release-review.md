## 観点

CLAUDE.md の「リリース」の 4 点を、手順書の 5 章の確認項目に沿って確かめる。

1. 全テストが Green
2. 仕様書の要求を満たしている（仕様書 8 章の受け入れ基準）
3. 動作環境の実機の確認（ユーザーが行う）
4. 発行物の設定（この一巡では、公開のワークフロー、公開物、版番号とタグ）

加えて、手順書とリリースノートの記述が、実際の公開物と合っているかを見る。

## 4. 発行物の設定

| 項目 | 結果 |
|------|------|
| ワークフローの起動 | `on:` は `workflow_dispatch` だけ。push では動かない |
| 権限 | 既定は `contents: read`。`contents: write` は `release` のジョブだけにある |
| 入力の扱い | `inputs` は `env` で渡し、`run` の中では環境変数として読む（`${{ }}` がスクリプトに入るのは `concurrency` の名前と `env` だけ） |
| 版番号とタグ | 版番号は `1.0.0` の形でなければ失敗し、同じタグがあれば、テストの前に失敗する。タグは `desktop-v1.0.0`、`console-v1.0.0`（仕様書 7.4） |
| Actions の版 | `actions/checkout@v7`、`actions/setup-dotnet@v6`（Web 版の `deploy.yml` と同じ） |
| リリースノートの節 | 「## デスクトップ版 1.0.0（公開前）」「## コンソール版 1.0.0（公開前）」がある。公開の日付への書き換えは、手順書 4 章の手順 1 |
| 公開物の名前 | ワークフローが作るファイルの名前と、リリースノートの「動かし方」に書いた名前が合う |
| Web 版への影響 | `deploy.yml` は変えていない |
| 事前の試し | ワークフローの手順を WSL の Ubuntu で流し、まとめたものを展開して動かした（手順書の 3 章） |

- ワークフローが GitHub の上で実際に動くのは、工程 16 の 1 回目である（手動でだけ動き、Release を作るので、事前に動かせない）。手元で流せなかったのは、タグの問い合わせ（`git ls-remote`）と、Release を作る `gh release create` の 2 つである。
