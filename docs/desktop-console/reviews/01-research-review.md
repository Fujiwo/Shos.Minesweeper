## 観点

Web 版の調査書レビュー（docs/reviews/01-research-review.md）と同じ観点で見た。

1. **正確さ**: 事実の記述が出典と合っているか。出典のない推測を事実として書いていないか
2. **網羅性**: CLAUDE.md の目的と、ユーザーが示した条件（Linux の上でビルド・テスト・公開、Windows のデスクトップ アプリとして動く）に対して、仕様書と設計に必要な調査がそろっているか
3. **一貫性**: 章どうし、CLAUDE.md、このリポジトリの今の構成（テストの枠組みの版など）と矛盾していないか
4. **引き継ぎやすさ**: 仕様書で決めるべき論点が漏れなく、選択肢と根拠の節が示されているか

重大度は次の 3 段階とする。

- **重大**: 仕様や設計の判断を誤らせるおそれがある
- **中**: 仕様書、UI デザイン、設計で必要な情報が欠けている
- **軽微**: 表現や精度の問題

## 良い点

- 実行環境で振る舞いが変わる点（インバリアント モードの正規化、Linux の上で発行した Windows 向けのアプリ、端末ごとの文字の幅）を、1.1.0 の B2 の教訓に照らして挙げ、確かめる時期（実装の最初の区切り）まで書いている。
- 決めていないことを、仕様書で決める論点（8 章）と、設計以降で決めること（9 章）に分けている。仕様書に作り方の話が混ざりにくい。
- WPF から Avalonia に改めた経緯（1.1）を、比べた候補と条件に合わない理由とともに残している。後から選び直すときの材料になる。
- Web 版から引き継ぐものを、そのまま使える部品（2.1）、共有を検討する部品（2.2）、見直しが要る仕様（2.3）に分け、2.3 から 8 章の論点の番号を指している。

## 残る課題

レビューでは解消できず、後の工程に持ち越すもの。

- Avalonia のヘッドレスのテストと xUnit v3 の 4 系の組み合わせ（指摘 1）、Linux の上で発行した Windows 向けのアプリが動くか（6.1）、ナレーターでライブ リージョンが読まれるか（4.5）は、実装の最初の区切りで確かめる。結果によっては、アーキテクチャー設計の決定を見直す。
- 日本語のフォント（指摘 3）は UI デザインで決め、実機で確かめる。
- 「出典未確認」とした項目（3.1 の Windows のマインスイーパー、3.2 の端末の慣習、5.5 の端末の既定の大きさ）は、仕様書で採るかどうかを決めるときに、方針として決めるか、実機で確かめる。
