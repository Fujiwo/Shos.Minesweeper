## 1. 概要

Web 版（1.1.0）と同じゲームを、次の二つの版として作る。

- **デスクトップ版**: Windows のデスクトップ アプリ。Avalonia UI で作る（ユーザーの決定、2026-09-27。調査書 1.1）。マウスとキーボードで遊ぶ。
- **コンソール版**: 端末の中で動くアプリ。キーボードだけで遊ぶ。

この仕様書は「何ができるか」を定める。ゲームのルールは Web 版の仕様書の 3 章をそのまま使い、ここでは繰り返さない（3 章）。画面の見た目（配置、色、記号、フォント）は UI デザイン（docs/desktop-console/03-ui-design.md）で、実現の方法はアーキテクチャー設計書以降で定める。

### 1.1 用語

Web 版の仕様書 1.1 の用語（マス、開く、数字、旗、コード、効果音、演出）に加えて、次の用語を使う。

| 用語 | 意味 |
|------|------|
| デスクトップ版 | Avalonia UI で作る Windows のデスクトップ アプリ |
| コンソール版 | 端末（Windows Terminal など）の中で動くアプリ |
| 升 | 端末で 1 文字の半角の英数字が占める幅。全角の文字は 2 升を占める |
| カーソル | キーボードで選んでいるマス。Web 版の仕様書 4.5 の「選択しているマス」と同じ |
| 状態の行 | コンソール版の画面で、勝敗などの知らせを出す行（5.2） |

## 3. ゲームの仕様

- ゲームのルール、難易度、ゲームの状態、地雷の配置、マスの操作の結果、コード、勝利と敗北の表示、ベストタイムの規則は、**Web 版の仕様書の 3 章のとおり**とする。二つの版で変えない。
- 入力された文字列の扱い（Web 版の仕様書 3.1。前後の空白を除き、NFKC で整えてから値として読む。全角の数字も受け付ける）も同じである。二つの版は、どの発行の形でも、全角の数字を受け付ける（調査書 5.9。実現の方法は設計で決める）。
- Web 版の仕様書 3 章のうち、ブラウザーに関わる文は次のとおり読み替える。
  - 3.8 のベストタイムの保存先（ブラウザー）と、保存できない環境の例（プライベートブラウズ）は、6.2 の保存先と保存できないときの扱いに読み替える。
  - 3.6 と 3.7 のうち、演出（Web 版の仕様書 5.7）に関わる文は、各版の演出の決まり（デスクトップ版は 4.7、コンソール版は 5.2）に従う。
  - 3.7 の「ブラウザーのタブが裏にあっても正しい値になるように」は、「ウィンドウが裏にあっても、ほかの画面を開いていても」と読み替える。経過時間は開始した時刻との差で計る。
- 最初に起動したときは初級を選ぶ（Web 版と同じ）。
- 盤面の上の表示（Web 版の仕様書 3.7）のうち、旗モードは、どちらの版にも置かない。効果音の切り替えは、デスクトップ版だけに置く。

## 4. デスクトップ版の仕様

### 4.1 動作環境

- Windows 11 の x64 を対象にする。ユーザーの条件は「Windows のデスクトップ アプリとして動く」ことである（調査書 1.1）。
- Windows 10 と Arm64 の Windows では、動く見込みはあるが、確かめないので対象外とする。
- macOS と Linux は対象外とする。Avalonia なら動かせるが、効果音の鳴らし方（調査書 4.6）、日本語のフォント（調査書 4.4）、実機での確認が増える。対象にする具体的な根拠がない。
- 利用者の PC に .NET のランタイムを入れる必要はない（7.1）。

### 4.2 画面の構成

- 画面は 1 つのウィンドウで、Web 版と同じく、盤面と、その上の表示（ツールバー）で構成する。
- ツールバーに置くものは、難易度の選択、残り地雷数、リセット（新しいゲーム）、経過時間、効果音の切り替えである。Web 版のツールバーから旗モードを除いたものである。
- メニュー バーは置かない。Windows の定番（調査書 3.1）はメニューだが、Web 版と同じツールバーにすると、同じ操作が同じ場所にあり、UI デザインも Web 版を土台にできる。
- 難易度の選択と、勝利したときの表示（勝利カード）は、Web 版と同じ内容とする（難易度ごとのベストタイム、カスタムの入力、もう一度・閉じる）。形は UI デザインで決める。

### 4.3 操作

| 入力 | 動作 |
|------|------|
| マウスの左クリック | 開く（開いた数字のマスではコード） |
| マウスの右クリック | 旗を立てる・外す |
| タッチのタップ、ペンのタップ | 左クリックと同じ |
| 矢印キー | カーソルを動かす |
| Space または Enter | カーソルのマスを開く（数字のマスならコード） |
| F | カーソルのマスの旗を立てる・外す |
| F2 | 同じ難易度で新しいゲームを始める（リセットと同じ） |
| Tab | 難易度の選択、リセット、効果音の切り替え、盤面の間を移動する（順序は UI デザインで決める） |

- マウスの操作は Web 版の仕様書 4.1 の「通常のモード」の行と同じである。左ボタンを押し続けてから離しても、左クリックとして扱う。
- 右クリックで、アプリのメニューは出さない。
- **タッチには特別には対応しない。** タップで開くことはできるが、長押しでの旗と旗モードは作らない。デスクトップ版はマウスとキーボードの PC を対象にし、タッチの画面の PC で旗を立てたいときは、右クリックに当たる操作（ペンのボタンなど）か F キーを使う。タッチを重視する利用者には、Web 版がある。
- キーボードの操作は Web 版の仕様書 4.5 と同じで、F2 を足した。F2 は Windows のマインスイーパーの定番の新しいゲームのキーである（調査書 3.1。出典未確認）。
- カーソルの初めの位置は、Web 版の仕様書 4.5 と同じ（前に選んでいたマス。初めてなら左上）。カーソルのマスは見て分かるようにする。

### 4.4 盤面の大きさとウィンドウ

- マスは正方形で、盤面全体をウィンドウの中に表示する。
- 起動したときと、難易度を変えたときは、盤面が既定のマスの大きさ（UI デザインで決める）で収まるように、ウィンドウの大きさを決め直す。ただし、画面（作業領域）に収まらないときは、画面に収まる大きさにする。Windows の定番（調査書 3.1）に合わせ、盤面の大きさに合ったウィンドウにするためである。
- 利用者がウィンドウの大きさを変えたら、盤面がウィンドウに収まる最大の大きさにマスを合わせる。上限と下限は Web 版の仕様書 5.2 と同じ（上限 48、下限 20。単位は Windows の拡大率を掛ける前の大きさ）とする。下限でも収まらないときは、盤面の領域をスクロールできるようにする。
- 盤面の縦と横は入れ替えない。PC の画面は横長で、上級（30×16）も入れ替えずに収まる（調査書 4.4、Web 版の調査書 7.4）。
- 画面の拡大率（DPI）が違うモニターの間でウィンドウを動かしても、ぼやけずに表示する（調査書 4.4）。

### 4.5 配色、ダークモード、フォント

- OS のライト・ダークの設定に合わせて配色を切り替える。OS の設定が変わったら、アプリを開いたまま切り替える。
- 数字の色、記号の形は、Web 版の仕様書 5.4 と同じ考え方とする（クラシックの色合いを踏襲し、背景とのコントラスト比 4.5:1 以上。旗、地雷、誤った旗、踏んだ地雷は色だけでなく形でも区別する）。具体的な色は UI デザインで決める。Web 版の色を使えるなら使う。
- ハイコントラストの設定には、特別な対応をしない。Web 版も対応していない（Web 版の仕様書 5.4）。
- 日本語の文字を日本語の字形で表示する（調査書 4.4）。フォントは UI デザインで決める。

### 4.6 効果音

- **Web 版の仕様書 5.6 と同じ**とする。鳴らす出来事と音、1 回の操作で 1 つだけ鳴らすこと、何も起きない操作で鳴らさないこと、続けて操作したときに重ねて鳴らすこと、既定で鳴らすこと、音量と長さ、音をプログラムで合成することを含む。音は Web 版と同じ定義（Presentation の効果音の部品）から作る（CLAUDE.md の「目的」）。
- 「重ねて鳴らす」を保つのは、Web 版と同じ手応えにするためである。これにより、`SoundPlayer` だけでは作れない（調査書 4.6）。鳴らす方法はアーキテクチャー設計で決める。
- 効果音の切り替えはツールバーに置き、マウスでもキーボードでも切り替えられる。オンかオフかを読み上げで分かるようにする。
- 消した設定はファイルに保存し、アプリを起動し直しても保つ（6.2）。保存できないときは、アプリを開いている間だけ保つ。
- Windows には iOS の消音スイッチに当たるものはない。音量は OS の音量に従い、アプリの中に音量の調整は置かない。
- 音を鳴らす仕組みに失敗しても（音の出力の機器がないなど）、ゲームは続けられる。そのときは鳴らないだけとする。

### 4.7 演出

- **Web 版の仕様書 5.7 と同じ**とする（0 の連鎖の波、負けの地雷の順の表示、勝ちの旗の弾み、旗の出現。演出の間も操作できる。新しいゲームで演出を終える。読み上げは演出を待たない）。
- OS の「アニメーション効果」の設定（設定のアクセシビリティ → 視覚効果）がオフのときは、演出をせず、結果をすぐに表示する。Web 版の「動きを減らす設定」に当たる（調査書 4.4）。
- 演出は、操作から画面に反映されるまでの時間（6.1）を延ばさない。

### 4.8 アクセシビリティ

- WCAG 2.2 のレベル AA を目安にする（Web 版の仕様書 6.3 と同じ目標。WCAG はウェブの基準だが、デスクトップのアプリにも当てはめて考える）。
- すべての操作をキーボードで行える（4.3）。フォーカスとカーソルの位置は見て分かるようにする。
- スクリーンリーダーには、次の対応を**必ず行う**。
  - 各マスに、位置と状態が分かる名前を付ける（Web 版と同じく「3 行 5 列、未開放」「3 行 5 列、2」）。
  - 勝利と敗北、新しいゲームを、読み上げで知らせる。文は Web 版と同じ（Presentation の読み上げの文）。
  - 効果音の切り替えの状態（オンかオフか）を読み上げで分かるようにする。
  - ツールバーの各要素に、Web 版と同じ名前を付ける（「難易度、初級」「残り地雷 10」「経過時間 12 秒」「新しいゲーム」「効果音」）。
- 盤面を表（行と列）として読み上げられるようにすることは**目標**とする。Avalonia で実現できるかは確かめていない（調査書 4.5）。実現できないときは、既知の制約としてリリースノートに書く。
- スクリーンリーダーでの確認は、Windows のナレーターで行う。

### 4.9 終わり方

- ウィンドウを閉じると終わる。プレイ中でも確認しない。Web 版でもタブを閉じれば確認なしで終わり、1 回のゲームは短く、失っても困らないからである。
- 途中のゲームは保存しない（9 章）。

## 5. コンソール版の仕様

### 5.1 動作環境

| OS | 確かめる端末 |
|----|--------------|
| Windows 11（x64） | Windows Terminal、従来のコンソール ホスト（conhost） |
| Linux（x64） | WSL の上の Linux を、Windows Terminal で使う |

- Windows 11 では、コンソールのアプリは既定で Windows Terminal の中で動く（調査書 5.1）。従来のコンソール ホストも設定で使えるので、両方を対象にする。二つは、あいまいな幅の文字の扱いなどが違う（調査書 5.4）。
- Linux は、開発に使う PC にある WSL で確かめる（CLAUDE.md の「git」にあるとおり、WSL を使っている）。Linux の端末の中では、Windows Terminal で確かめたものを対象とし、ほかの端末（GNOME Terminal など）では確かめない。
- macOS は対象外とする。実機で確かめる手段がないためである。
- 端末の大きさは 80 列×24 行以上を前提にする（5.5）。
- 利用者の PC に .NET のランタイムを入れる必要はない（7.1）。
- Linux では、.NET は OS の ICU のライブラリを使う（調査書 5.9）。ICU の入っていない Linux では起動できないので、ICU をアプリに含めるか、利用者に入れてもらうかを設計で決める。利用者に要るものがあれば、リリースノートに書く。全角の数字の入力（3 章）を保つため、インバリアント モードで ICU を避ける方法は、NFKC の代わりを用意しない限り使わない。

### 5.2 画面の構成

- 端末の画面全体を使う。起動したら端末の「代替画面」に切り替え、終わったら元の画面に戻す（調査書 3.2）。終わった後の端末に、ゲームの画面を残さない。
- 画面は、上から次の順に並べる。
  1. 上の行: 難易度、残り地雷数、経過時間（Web 版の仕様書 3.7 のうち、リセット・旗モード・効果音を除いたもの。リセットはキーで行う）
  2. 盤面
  3. 状態の行: 勝敗の知らせ、入力の誤りなど
  4. キーの案内の行: 主なキー（5.3）
- 経過時間は、キーを待っている間も 1 秒ごとに表示を進める。
- 演出はしない。結果はすぐに表示する。端末では、動きの表現に使える手段が少なく、描き直しが増えると画面がちらつく（調査書 5.3）。
- 勝利したときは、状態の行に「クリア。N 秒。」とベストタイムの知らせ（Web 版の読み上げの文と同じ内容）を出す。Web 版の勝利カードに当たるものは置かない。

### 5.3 操作

| キー | 動作 |
|------|------|
| 矢印キー、または H・J・K・L | カーソルを動かす（H 左、J 下、K 上、L 右） |
| Space または Enter | カーソルのマスを開く（数字のマスならコード） |
| F | カーソルのマスの旗を立てる・外す |
| N | 同じ難易度で新しいゲームを始める（Web 版のリセット） |
| D | 難易度の選択の画面を開く（5.7） |
| ? | キーの一覧（ヘルプ）を出す。何かキーを押すと戻る |
| Q | 終わる（5.9） |
| Ctrl+C | 終わる（5.9） |

- 英字のキーは、大文字と小文字を区別しない。日本語の入力（IME）がオンのままでも操作できるかは、実装のときに確かめる。
- H・J・K・L は、端末のプログラムの慣習（調査書 3.2）に合わせて加える。F（旗）とはぶつからない。
- カーソルの初めの位置は左上とし、新しいゲームでも前に選んでいたマスを保つ（Web 版の仕様書 4.5 と同じ）。カーソルは端で止まり、反対側には回り込まない。
- **マウスには対応しない。** `System.Console` にマウスの API がなく、OS ごとの処理かライブラリが要る（調査書 5.2）。端末のゲームはキーボードで遊ぶのが慣習である（調査書 3.2）。

### 5.4 盤面の表し方

- 1 マスを 2 升で描く（記号 1 升と、区切りの空白 1 升）。上級（30 列）の盤面を、枠を含めて 80 列に収めるためである（調査書 5.5）。
- マスの記号は、ASCII の文字だけを使う。幅があいまいな文字や絵文字を使うと、端末によって盤面の列がずれる（調査書 5.4）。どの文字にするかは UI デザインで決める。
- 未開放、旗、開いたマス（数字と 0）、地雷、踏んだ地雷、誤った旗は、色がなくても記号で区別できるようにする。
- カーソルのマスは、色がなくても分かるようにする（反転表示など。UI デザインで決める）。

### 5.5 画面の大きさ

- 初級・中級・上級の盤面は、80 列×24 行の端末に収まるようにする（調査書 5.5）。
- 端末が盤面と表示に対して小さいときは、盤面を描かず、「端末の画面を広げてください」と、要る大きさを知らせて待つ。待っている間に受け付けるのは、終わる操作（Q、Ctrl+C）と難易度の選択（D）だけとする。端末を広げたら、そのままゲームを続ける。カスタムの最大（30×24）は、24 行の端末には収まらないので、この知らせが出る。
- カスタムの範囲は、Web 版と同じ（幅 5〜30、高さ 5〜24）とし、端末の大きさでは制限しない。盤面をスクロールする形は、カーソルの位置が見えにくくなるので採らない。
- 端末の大きさが変わったら、描き直す。ゲームの状態はそのまま続ける（Web 版の仕様書 5.3 と同じ）。

### 5.6 色

- 色は、端末の 16 色（`ConsoleColor`）で付ける。数字の色は、Web 版のクラシックの色合い（Web 版の仕様書 5.4）に近い色を選ぶ。具体的な色は UI デザインで決める。
- 背景は端末の背景のままにする。端末の配色は利用者の設定で決まるので、コントラスト比は保証しない（既知の制約。調査書 5.6）。
- 環境変数 `NO_COLOR` が空でない値で設定されているときは、色を付けない（調査書 3.2）。記号と反転表示だけで遊べる（5.4）。

### 5.7 難易度の選択とカスタムの入力

- D キーで、難易度の選択の画面を開く。初級、中級、上級、カスタムと、それぞれのベストタイム（カスタムは記録しない）を並べる。Web 版の難易度ダイアログと同じ内容である。
- 数字のキー（1〜4）か、矢印キーと Enter で選ぶ。Esc で、選ばずにゲームに戻る。
- カスタムを選んだら、幅、高さ、地雷数を 1 行ずつ尋ねる。尋ねるときに、入力できる範囲を示す（地雷数の範囲は、入力した幅と高さから求める）。
- 入力した文字列は、3 章のとおり整えてから読む。範囲の外や整数でないときは、何が誤りかを状態の行に出し、その値を尋ね直す。Esc で、カスタムをやめてゲームに戻る。
- 難易度を選ぶと、その難易度で新しいゲームを始める。プレイ中のゲームは確認なしで破棄する（Web 版の仕様書 3.1 と同じ）。
- 選ばずに戻ったときは、前のゲームをそのまま続ける。難易度の選択の画面とヘルプ（5.3）を開いている間も、プレイ中のゲームの経過時間は進む（Web 版の難易度ダイアログと同じ。止めると、画面を開いて考える時間を稼げてしまう。Web 版の UI デザインの 2.3 と、その決定の表）。

### 5.8 アクセシビリティ

- すべての操作をキーボードで行う（5.3）。
- **スクリーンリーダーでの操作は対象外とする。** 画面全体を描き直す端末のアプリは、スクリーンリーダーでは追いにくく（調査書 8 章の論点 19）、対応するには行を出力する別の形が要る。スクリーンリーダーを使う利用者には、Web 版とデスクトップ版がある。
- ただし、勝敗や新しいゲームの知らせは、Web 版の読み上げの文と同じ内容を状態の行に出す。
- 色がなくても遊べる（5.4、5.6）。

### 5.9 終わり方

- Q キーか Ctrl+C で終わる。プレイ中でも確認しない（4.9 と同じ理由）。
- 終わるときは、例外で終わる場合も含めて、端末の状態（代替画面、カーソルの表示、色）を元に戻す（調査書 5.3）。

## 6. 非機能の仕様

### 6.1 性能

- 開く、旗を立てるなどの操作から画面に反映されるまでを、上級の盤面で 100 ミリ秒以内とする（目標。Web 版の仕様書 6.2 と同じ）。デスクトップ版はカスタムの最大（720 マス）でも満たす。
- 起動してから盤面が表示されるまでを、3 秒以内とする（目標。開発に使う PC で確かめる）。
- 経過時間の表示は、ほかの処理の間も 1 秒ごとに進む。経過時間は開始した時刻との差で計る（Web 版と同じ）。

### 6.2 データとプライバシー

- 外部のサーバーとは通信しない。
- 保存するものは次のとおりである。保存先は、利用者ごとのアプリのデータの場所（調査書 4.8、5.8）とする。

| 版 | 保存するもの |
|----|--------------|
| デスクトップ版 | ベストタイム、効果音を鳴らすかどうか |
| コンソール版 | ベストタイム |

- **ベストタイムは、版ごとに別のファイルに保存し、共有しない。** 同じ PC で二つの版を同時に動かしたときに、後から書いた方が先の記録を消すおそれがない（調査書 4.8）。保存の形式は Web 版と同じ（`BestTimesJson`）とする。
- 保存できないとき（書き込みの権限がないなど）でも、ゲームは遊べる。そのときは、アプリを開いている間だけ保つ（Web 版の仕様書 3.8 と同じ）。保存したファイルが壊れていても、記録なしとして起動する。
- ウィンドウの位置と大きさ、最後に選んだ難易度は、覚えない。Web 版も覚えておらず（Web 版の仕様書 6.4）、起動のたびに初級から始めても困らない。

### 6.3 言語

- 画面の文言は、両方の版で日本語だけとする（Web 版の仕様書 5.5 と同じ）。
- 文言は Web 版と同じ言い方にそろえる（難易度の名前、読み上げの文、勝利の知らせなど）。

## 7. 配布と公開

### 7.1 配布の形

- 両方の版を、**自己完結の単一ファイル**として配る。利用者の PC に .NET のランタイムを入れる必要がなく、ファイルを 1 つ置けば動く。
- 配る実行ファイルは次の 3 つである。

| 版 | 対象 | 実行ファイル |
|----|------|--------------|
| デスクトップ版 | Windows（x64） | Windows の実行ファイル（.exe） |
| コンソール版 | Windows（x64） | Windows の実行ファイル（.exe） |
| コンソール版 | Linux（x64） | Linux の実行ファイル |

- Native AOT は使わない。デスクトップ版の Windows 向けは Linux の上で作れず（調査書 6.1）、ユーザーの条件（Linux の上で公開）に合わない。コンソール版だけ AOT にすると、二つの版で発行の形が分かれ、インバリアント モードの注意（調査書 5.9）も増える。
- トリミングは使わない。発行物は小さくなるが、トリミングで壊れていないかを確かめる手間が増える。大きさの目標は置かない。
- .NET ツール（NuGet）としては配らない。利用者に .NET の SDK が要るからである。
- 発行は Linux の上で行う（ユーザーの条件。調査書 1.1）。Linux の上で発行した Windows 向けの実行ファイルが動くかは、実装の最初の区切りで確かめる（調査書 6.1）。

### 7.2 公開先

- このリポジトリの GitHub Releases に、実行ファイル（zip などにまとめたもの）を置く。GitHub のリポジトリのページから、Releases を辿れる。
- 各リリースの説明に、その版のリリースノート（使い方、警告の越え方を含む）を書く。
- Web 版のページ（GitHub Pages）からのリンクは置かない（Web 版を変えないため）。このリポジトリには今 README がない。README を作って案内するかは、リリース準備（工程 14）で決める。
- インストーラー、Microsoft Store、winget は使わない。
- 公開の操作は、Web 版と同じく、リリースレビューの承認とユーザーの指示があるときだけ行う（CLAUDE.md の「リリース」）。

### 7.3 署名

- 実行ファイルに署名はしない。コード署名の証明書が要り、個人の無料のアプリには負担が大きい。
- そのため、Windows では SmartScreen の警告が出る（調査書 6.3）。警告の越え方（「詳細情報」から実行する）を、リリースノートで案内する。
- Linux では、実行の許可（`chmod +x`）が要る。その手順もリリースノートで案内する。

### 7.4 版番号とタグ

- 版ごとに版番号を付け、どちらも 1.0.0 から始める。Web 版の版番号（1.1.0）とは独立させる。Web 版を変えずにデスクトップ版だけを直す、といった更新ができるようにするためである。
- タグは `desktop-v1.0.0`、`console-v1.0.0` とする。Web 版の `v1.x.x` とぶつからない。
- リリースノートは版ごとに書く（置き場所はリリース準備で決める）。

## 8. 受け入れ基準

リリースレビュー（工程 15）では、少なくとも次を確かめる。

### 8.1 両方の版

1. 初級・中級・上級・カスタムで、勝利と敗北の両方までゲームを進められる。
2. 最初に開いたマスが、どの難易度でも必ず 0 になる。未開始のうちに旗を立てても同じである。
3. コードと旗が、Web 版の仕様書 3.4、3.5 のとおりに動く。
4. キーボードだけでゲームを最後まで進められる。
5. ベストタイムが記録され、起動し直しても残る。二つの版の記録は混ざらない。
6. 保存ができないとき（保存先に書き込めないとき）でも、ゲームを最後まで遊べる。
7. カスタムの入力で、全角の数字と前後の空白を受け付ける（配布する実行ファイルで確かめる）。
8. 上級の盤面で、操作が 100 ミリ秒以内に反映される（体感で遅れを感じない）。起動から 3 秒以内に盤面が表示される。
9. Linux の上で、全テストが Green になり、配る実行ファイルを発行できる。

### 8.2 デスクトップ版

10. マウスとキーが 4.3 の表のとおりに動く（F2 を含む）。左ボタンを押し続けても旗にならない。
11. 難易度を変えるとウィンドウの大きさが盤面に合い、ウィンドウの大きさを変えるとマスの大きさが合う（4.4）。
12. OS のライトとダークの両方で、数字が読める。OS の設定を変えると、開いたまま切り替わる。
13. Web 版の仕様書 5.6 の表の各出来事で、対応する効果音が鳴る。何も起きない操作では鳴らず、続けて操作すると重ねて鳴る。効果音を消すと鳴らなくなり、その設定は起動し直しても残る。
14. 演出が見え、演出の間も操作できる。OS の「アニメーション効果」をオフにすると、演出をせずに結果がすぐ表示される。
15. ナレーターで、マスの位置と状態、勝敗、効果音の切り替えの状態が読み上げられる。
16. 拡大率の違うモニターの間でウィンドウを動かしても、ぼやけない（確かめられる環境がある場合）。

### 8.3 コンソール版

17. Windows Terminal、従来のコンソール ホスト、WSL の Linux のそれぞれで、盤面の列がずれずに表示される。
18. 5.3 の表のキーのとおりに動く。
19. `NO_COLOR` を設定すると色が付かず、それでも遊べる。
20. 端末を小さくすると広げるように知らせ、広げるとゲームが続く。
21. Q、Ctrl+C のどちらで終わっても、端末が元の状態（元の画面、カーソルの表示、色）に戻る。

## 9. 対象外

Web 版の仕様書 9 章の対象外（？マーク、左右同時クリック・中クリックでのコード、No Guessing モード、統計、カスタムのベストタイム、英語など他の言語、ヒント、やり直し、アプリの中での音量の調整、BGM、経過時間の 1 秒ごとの音、記録の消去、ゲームの途中経過の保存）は、両方の版でそのまま対象外とする。オフライン対応（PWA）は、両方の版がオフラインで動くので当てはまらない。

この一巡で加える対象外:

| 機能 | 対象外とする理由 |
|------|------------------|
| デスクトップ版の長押しでの旗、旗モード | デスクトップ版はマウスとキーボードの PC を対象にする（4.3）。タッチには Web 版がある |
| デスクトップ版のメニュー バー | Web 版と同じツールバーで、同じ操作ができる（4.2） |
| デスクトップ版のハイコントラストへの特別な対応 | Web 版も対応していない（4.5） |
| デスクトップ版の macOS・Linux 対応 | 対象にする根拠がなく、音、フォント、実機の確認が増える（4.1） |
| コンソール版のマウス、効果音、演出 | 5.2、5.3。効果音は CLAUDE.md の「目的」のとおり |
| コンソール版のスクリーンリーダーでの操作 | 画面全体を描き直す形では追いにくい（5.8）。Web 版とデスクトップ版がある |
| コンソール版の macOS 対応 | 実機で確かめる手段がない（5.1） |
| 二つの版のベストタイムの共有 | 同時に動かしたときに記録が消えるおそれがある（6.2） |
| ウィンドウの位置と大きさ、最後の難易度の記憶 | Web 版も覚えていない（6.2） |
| インストーラー、自動更新、Microsoft Store・winget での配布 | 単一ファイルを置けば動く（7.1、7.2） |
| 実行ファイルへの署名 | 証明書が要る。警告の越え方を案内する（7.3） |
