# スキルの評価の課題（sustainable-code-jp）

| 項目 | 内容 |
|------|------|
| 目的 | スキルの効果を、同じ課題をスキルあり・なし・改良の前後で流して比べる（docs/for-skills/reviews/skill-evaluation.md の 12.6 の S14、12.8） |
| 作成日 | 2026-09-29 |
| 状態 | ユーザーの決定（12.9 の推す案）で作った。最初の 32 回の結果は skill-evaluation.md の 12.11 にある |

## ファイル

| ファイル | 中身 | 被験者に渡すか |
|----------|------|----------------|
| tasks/T1.md〜T8.md | 課題の文（このプロジェクトの記録にある場面を、単独で読める形にしたもの） | 渡す |
| tasks/T6/run_tests.sh | T6 のテストを流す口。流すたびに、どのファイルがあり、結果が何だったかを `test-log.txt` に書く | 渡す |
| criteria.md | 合格の基準（結果の形だけで判定する） | 渡さない（判定する側だけが読む） |

## 条件

| 条件 | スキル | 作り方 |
|------|--------|--------|
| A | なし | スキルのファイルを渡さず、使わないよう指示する |
| B | 改良の前 | コミット `f1ff4e4` の `.claude/skills/sustainable-code-jp/` を取り出した写し |
| C | 今の版 | コミット `cc780aa` の同じフォルダーの写し |
| D | 改良の後（S11〜S13） | C の写しに、12.6 の S11、S12、S13 を入れたもの |

- スキルの写しは、会話の作業用のフォルダーに作る。リポジトリのスキルのファイルは変えない。
- 被験者は、文脈を持たないサブエージェントである。スキルのある条件では、Skill ツールで呼ぶ代わりに、写しの SKILL.md を読み、その表に従って references を読むよう指示する（呼び出しをファイルの読み込みで置き換えた）。
- 課題ごとの作業フォルダーに課題の文だけを写し、そのフォルダーの外（リポジトリの docs やコード）を読まないよう指示する。

## 判定

- 判定する側のサブエージェントに、課題の文、合格の基準、4 つの条件の出力を、条件を伏せ、順を課題ごとに変えて渡す。合否と理由を返させる。
- 合否が割れにくいものも含め、全体の 1 割と、判定する側が「確信が低い」としたものは、ユーザーが確かめる。

## 限界（この流し方で分けられないもの）

- サブエージェントには、このリポジトリの CLAUDE.md が入る。「コーディング規範」の節（P1〜P5 と、sustainable-code-jp を使うという定め）はどの条件にも同じく入るので、条件 A も P1（整合・正しさ）の観点を持つ。条件の差は、スキルの本文の差だけを表す。
- スキルの一覧（description）は、どの条件でもサブエージェントの文脈にある。条件 A は、それを使わないよう指示しただけである。
- 呼び出しをファイルの読み込みで置き換えたので、description による起動と、会話の圧縮の後の振る舞いは測れない。
- 1 条件 1 回では、ばらつきと差を分けられない。差の出た課題だけを、条件ごとに 5 回に増やす（12.8）。
